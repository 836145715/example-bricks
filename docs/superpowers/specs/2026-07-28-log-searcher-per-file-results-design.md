# 日志查询按文件提交结果设计

## 目标

保留本地与 SSH 的顺序检索，任一日志文件完成后立即将其结果和完成状态交给对应 Tab，而不等待后续文件。

## 方案

在 Go 检索层增加文件开始与完成回调。存储模式在开始时将文件标记为 `searching`，完成时调用 `FinishFile` 并立即发送一次 `searchState`。前端沿用现有按 Tab 的 `peek_search_results` 读取逻辑。

## 边界

- 不改变文件查询顺序。
- 不改变 `maxCount` 的“每文件最新 N 条”语义。
- 整体取消或不可恢复错误仍由 `FinishRun` 处理未完成文件。

## 验证

新增回归测试，断言第一个文件完成时：其状态已为 `success`、结果可读取，第二个文件仍为 `queued`。
